# Gennect CRM — система для УБТ-команди

Робочий MVP під цикл **ресурси → фарм → контент → залив → трекінг → виплати → аналітика**.
Закриває те, що зазвичай ламається в Google Sheets на 15+ людях: облік акаунтів і девайсів,
звʼязка «креатив → акаунт → публікація → конверсія», автоматичний розрахунок ЗП і розрізи ROI.

Нуль зовнішніх залежностей: Node 22 (вбудований `node:sqlite`, `node:crypto`), фронтенд —
ES-модулі без збірки. Піднімається однією командою, без Docker, Postgres і CI на старті.

## Запуск

```bash
git clone https://github.com/eugene263/CRM.git && cd CRM
cp .env.example .env                       # мінімум — задати CRM_SECRET_KEY
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # ключ шифрування

npm run seed          # створює власника + демо-дані (28 акаунтів, 400+ заливів, 30 днів статистики)
npm run seed -- --admin   # тільки власника, без демо — для бойового старту
npm start             # http://localhost:3000
npm test              # 16 інтеграційних перевірок: RBAC, постбеки, ЗП, аудит
```

Демо-логіни після сіду: `owner@gennect.local / gennect-admin`, далі `head@`, `lead.a@`,
`creator1@`, `editor@`, `farmer@`, `finance@gennect.local` — пароль `demo1234`.
Зайдіть під крієйтором і під власником: видно різні дані, це і є перевірка RBAC.

Docker: `docker compose up -d --build` (адмінка 3000, постбеки 3001, щоденний бекап бази у `./backups`).

## Трекінг

Лінк: `https://<host>/r/<slug>` → редірект на офер із підстановкою
`sub1=account_id`, `sub2=creative_id`, `sub3=user_id`, `sub4=post_id`, `click_id=<id>`.

Постбек партнерці (токен видається при створенні партнерки, поле `postback_token`):

```
https://<host>:3001/pb/<token>?click_id={click_id}&status=approved&event=dep
   &payout=45&currency=USD&external_id={conversion_id}
```

- `status`: `hold|pending|lead` → холд, `approved|confirmed` → апрув, `rejected|trash` → відхилено, `paid` → виплачено
- `event`: `reg|dep|sale|click`
- дедуплікація за парою `partner_id + external_id`; повторний виклик **оновлює статус**, а не створює дубль
- якщо `click_id` знайдено, звʼязка акаунт/креатив/крієйтор підтягується автоматично; інакше беруться subid
- постбеки слухає окремий процес (`CRM_ROLE=postback node server.js`), щоб сплеск конверсій не клав адмінку

Якщо у вас уже є Keitaro/Binom — лишайте трекер собі, а сюди шліть постбеки тим самим форматом.

## Формула ЗП

`ЗП = фікс + % від профіту + бонус за KPI`

- профіт крієйтора/монтажера/фармера — його апрувнуті конверсії мінус витрати, повішані на нього
- профіт тімліда — по його команді; хеда/власника — по компанії
- бонус нараховується, коли факт за метрикою (`posts` / `deps` / `profit`) досяг цілі
- правило шукається спершу персональне, потім по ролі, з урахуванням `active_from`
- холд у профіт не входить — платимо з апруву
- періоди зі статусом «виплачено» перерахунок не чіпає

Налаштування — розділ «Правила ЗП», розрахунок — «Фінанси → Розрахунок ЗП» (перегляд, потім «Нарахувати»).

## Безпека

- паролі акаунтів/пошт/проксі шифруються AES-256-GCM, ключ лише в `CRM_SECRET_KEY`, у БД його немає
- у списках секрети завжди `••••••`; розкриття — окремий запит із роллю `secrets` і записом в аудит
- експорт CSV доступний не всім ролям, пишеться в аудит і містить водяний знак з email того, хто вивантажив
- паролі співробітників — scrypt; 2FA — TOTP; сесії в БД з терміном дії, кука `HttpOnly; SameSite=Lax`
- rate-limit на логін (10/хв з IP) і на постбеки (600/хв на токен)
- адмінку тримайте за VPN або IP-whitelist на nginx; назовні світіть лише порт постбеків
- бекап бази — щодня (у compose є окремий контейнер); раз на місяць перевіряйте відновлення

## Масштабування

SQLite тримає команду до ~30 осіб і кілька мільйонів рядків. Коли впреться:

1. `src/db.js` — єдина точка доступу до БД; переїзд на PostgreSQL = заміна драйвера, схема в `src/schema.sql` сумісна.
2. `clicks` і `conversions` винесені в окремі таблиці навмисно — вони першими їдуть у ClickHouse, решта модулів їх торкається лише через `src/analytics.js`.
3. Фонові задачі зараз у `setInterval` в `server.js` — виносяться в BullMQ/Celery без змін у бізнес-логіці.

## Далі (за етапністю з ТЗ)

- **v1**: інтеграція з Keitaro/Binom по API, S3/R2 для файлів креативів із превʼю, звірка сум з API партнерок
- **v2**: ClickHouse, прогноз вигорання звʼязок на історії, мобільний інтерфейс для крієйторів, публічне API

Автозбір метрик із TikTok/IG свідомо не робили: він найнестабільніший і ламається щомісяця.
Поки що — ручне внесення або імпорт CSV, як і рекомендує етапність.

## Структура

```
.
  server.js            точка входу: адмінка/API + окремий сервіс постбеків
  src/
    schema.sql         схема БД
    db.js              доступ до БД, аудит
    entities.js        опис сутностей → з нього будуються і API, і форми в UI
    rbac.js            матриця прав, скоупи, приховування полів
    api.js             REST: генерик-CRUD + постбеки, редіректи, експорт, імпорт
    auth.js            сесії, 2FA, паролі
    crypto.js          scrypt, AES-256-GCM, TOTP
    analytics.js       дашборд, розрізи, вигорання, життя акаунтів
    finance.js         ЗП і P&L
    telegram.js        черга сповіщень
    seed.js            власник + демо-дані
  public/              інтерфейс (ES-модулі, без збірки)
  test/smoke.test.js   інтеграційні перевірки
```

Додати поле в будь-який розділ — один рядок у `src/entities.js`: воно зʼявиться і в API, і в таблиці, і у формі.
